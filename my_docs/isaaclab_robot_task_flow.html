Isaac Lab 机器人任务接入流程

这份文档按你当前的 R11 项目路径梳理：业务方给 assets 后，我们如何检查资产、写 isaaclab_assets/robots/seres_r11.py，再写 env_cfg，最后在 __init__.py 注册任务并验证。

1. 总体流程

你的理解基本正确：通常是先拿到业务方给的资产，然后把机器人资产封装成 ArticulationCfg，再在某个任务的 env_cfg 中引用它，最后注册成一个 Gymnasium 任务 ID，供训练、回放、teleop 或数据采集脚本使用。

Step 1: 接收和整理资产 确认 USD、mesh、贴图、URDF/MJCF、关节/连杆命名、物理参数、初始姿态。
Step 2: 写 robot cfg 在 isaaclab_assets 里定义机器人如何 spawn、初始状态、执行器参数。
Step 3: 写 env_cfg 定义任务场景、机器人和物体摆放、action、observation、termination、event。
Step 4: 注册和运行 在任务包 __init__.py 中注册 ID，然后用脚本创建环境并验证。
最重要的分工：robots/xxx.py 只回答“这个机器人在仿真里怎么被加载和驱动”；env_cfg 回答“这个机器人要在哪个任务里做什么，以及智能体/teleop 能看到什么、控制什么、什么时候结束”。

2. assets 目录应该有什么

业务方通常不会只给一个 USD。USD 是场景描述入口，但 USD 往往会引用 mesh、材质、贴图或 payload。 对一个机器人项目，建议 assets 目录至少整理成下面这些内容。

类别 建议内容 为什么需要
主资产 robot.usd、robot.usda 或 robot.usdc Isaac Lab 的 UsdFileCfg.usd_path 会指向它，用于在场景中生成机器人。
几何资源 meshes/ 下的 .obj、.stl、.dae、.fbx 等 USD 可能外部引用 mesh；缺失会导致机器人不可见或加载报错。
材质贴图 materials/、textures/、.mtl、.png、.jpg 影响可视化，也能帮助确认连杆方向和装配是否正确。
源模型 .urdf、.mjcf、原始 CAD/导出说明 后续排查关节轴、link 名、mimic、限位和 IK 时非常有用；Pink IK 这类控制器也常需要 URDF。
物理参数表 关节限位、速度上限、力矩上限、质量、惯量、减速器、摩擦、PD 建议值 用于写 ImplicitActuatorCfg 或显式电机模型，避免机器人软、抖、爆炸或动作不真实。
命名说明 joint/link 命名表、末端 link、脚底 link、base link、手指 mimic 关系 env_cfg 里 action、observation、termination、contact sensor、IK frame 都依赖这些名字。
校验资料 默认站姿、零位图、业务期望姿态、真实机器人截图或视频 用于判断 init_state、朝向、坐标系和关节正方向是否正确。

推荐目录结构

IsaacLab/
  assets/
    seres_r11/
      r11_0615.usd
      r11_0615.urdf              # 如果 IK、排查、二次转换需要，建议保留
      meshes/
        r11_0615/
          *.obj
          *.mtl
      docs/
        joint_names.md
        actuator_limits.xlsx
        zero_pose.png
如果业务方只给 USD，也要确认 USD 是否已经内嵌或能解析所有依赖。常见问题是 USD 中引用了绝对路径、 Windows 路径、Omniverse/Nucleus 路径，换机器后加载失败。

3. robot py 的目的和内容

source/isaaclab_assets/isaaclab_assets/robots/seres_r11.py 的核心目的是定义机器人资产配置， 也就是一个或多个 ArticulationCfg。它不是任务配置，也不关心 pick/place、行走、teleop 这些业务逻辑；它只关心“机器人本体如何在仿真里稳定、可控、可复用”。

robot py 应该写什么

模块 你要写的内容 R11 示例
路径常量 资产根目录、USD 路径、必要时 URDF/mesh 路径。 ISAACLAB_ASSETS_DIR、R11_USD_PATH
命名分组 腿、脚、腰、臂、头、手、末端、接触 link 等 joint/link 名或正则。 LEG_JOINT_NAMES、ARM_JOINT_NAMES、FEET_LINK_NAMES
物理/执行器常量 力矩上限、速度上限、刚度、阻尼、armature、friction 等。 EFFORT_LIMIT_*、STIFFNESS_*、DAMPING_*
spawn 如何从 USD 生成机器人，以及刚体、关节根、自碰撞、contact sensor 等属性。 sim_utils.UsdFileCfg(...)
init_state 默认根位置、根姿态、关节初始位置、关节初始速度。 ArticulationCfg.InitialStateCfg(...)
actuators 按关节组定义执行器模型、被控制关节、力矩/速度限制、PD 参数。 legs、feet、waist、arms、hands
派生配置 在基础机器人上 copy/replace 出固定底座、高 PD、无手版本等变体。 R11_A2_HIGH_PD_CFG

最小骨架

import os

import isaaclab.sim as sim_utils
from isaaclab.actuators import ImplicitActuatorCfg
from isaaclab.assets.articulation import ArticulationCfg

ASSET_DIR = os.path.abspath(os.path.join(os.path.dirname(__file__), "../../../../assets/my_robot"))
USD_PATH = os.path.join(ASSET_DIR, "my_robot.usd")

MY_ROBOT_CFG = ArticulationCfg(
    spawn=sim_utils.UsdFileCfg(
        usd_path=USD_PATH,
        activate_contact_sensors=True,
        rigid_props=sim_utils.RigidBodyPropertiesCfg(
            disable_gravity=False,
            linear_damping=0.0,
            angular_damping=0.0,
        ),
        articulation_props=sim_utils.ArticulationRootPropertiesCfg(
            enabled_self_collisions=True,
            solver_position_iteration_count=8,
            solver_velocity_iteration_count=4,
        ),
    ),
    init_state=ArticulationCfg.InitialStateCfg(
        pos=(0.0, 0.0, 1.0),
        joint_pos={".*": 0.0},
        joint_vel={".*": 0.0},
    ),
    actuators={
        "body": ImplicitActuatorCfg(
            joint_names_expr=[".*"],
            effort_limit_sim=100.0,
            velocity_limit_sim=10.0,
            stiffness=100.0,
            damping=10.0,
        ),
    },
)

robot py 不应该承担什么

  • 不应该写任务成功条件，例如物体是否放到目标区域。
  • 不应该写 policy observation 细节，例如给算法拼哪些状态。
  • 不应该写场景桌子、目标物、灯光和随机化，除非这些是机器人本体的一部分。
  • 不应该绑定某一个训练算法配置，例如 RSL-RL、robomimic、skrl 的超参数。

4. env_cfg 的目的和内容

env_cfg 是任务配置。它把机器人、物体、场景、控制方式、观测、终止条件和 reset 逻辑组合起来， 形成一个可被 ManagerBasedRLEnv 创建的环境。

env_cfg 常见组成

配置类 作用 通常写什么
SceneCfg 定义世界里有什么。 机器人、桌子、目标物、地面、灯光、相机、传感器、每个 env 的 spacing。
ActionsCfg 定义外部输入如何作用到机器人。 关节位置控制、关节速度控制、IK action、手爪 action、teleop action。
ObservationsCfg 定义 policy 或 recorder 能看到什么。 关节状态、根状态、物体状态、末端位姿、相机图像、上一帧 action。
RewardsCfg RL 训练时定义奖励。 到目标距离、姿态误差、动作平滑、能耗、成功奖励。纯 teleop/数据采集可为 None。
TerminationsCfg 定义 episode 什么时候结束。 超时、失败掉落、机器人摔倒、任务成功。
EventCfg 定义 reset 或运行过程事件。 重置机器人、随机化物体位姿、随机化材质/质量/摩擦、重置 action target。
EnvCfg 把上面所有 manager 拼起来。 scene、actions、observations、terminations、events、仿真频率。

R11 pick-place 里的对应关系

  • ObjectTableSceneCfg：放置 packing table、object、R11 robot、ground、light。
  • ActionsCfg：使用 PinkInverseKinematicsActionCfg 控制双腕末端和手部关节。
  • ObservationsCfg：记录 action、机器人关节/root、物体位姿、左右末端位姿、手/头关节状态。
  • TerminationsCfg：包括 time_out、物体掉落、pick-place 成功。
  • EventCfg：reset 场景、轻微随机化 object 位姿。
  • PickPlaceR11EnvCfg：设置 decimation、episode_length_s、sim.dt、PhysX buffer、XR/teleop pipeline。

写 env_cfg 的推荐顺序

  1. 先只写 SceneCfg，把机器人和地面 spawn 出来，确认不爆炸、不丢 mesh。
  2. 加入任务物体、桌子、目标区域，确认坐标系和高度正确。
  3. 加入最简单的 ActionsCfg，先用 joint position action 或固定 action 验证机器人能动。
  4. 再切到业务需要的 action，例如 IK、motion controller、hand tracking。
  5. 加入 ObservationsCfg，保证维度稳定，命名和 link/joint 匹配。
  6. 加入 TerminationsCfg 和 EventCfg，让 episode 能正确 reset、成功、失败。
  7. 最后补 rewards、curriculum、domain randomization 或数据采集配置。
如果你的目标是 teleop 或模仿学习采集数据，rewards = None 是可以的；如果目标是强化学习训练， 就需要补 RewardsCfg 和算法侧 agent 配置。

5. 任务注册

写完 env_cfg 后，通常需要在任务目录的 __init__.py 中通过 gym.register 注册任务。注册的目的，是把“环境 ID”映射到“环境类”和“配置类”。

当前项目示例

gym.register(
    id="Isaac-PickPlace-R11-Abs-v0",
    entry_point="isaaclab.envs:ManagerBasedRLEnv",
    kwargs={
        "env_cfg_entry_point": (
            "isaaclab_tasks.manager_based.manipulation.pick_place."
            "pickplace_seres_r11_env_cfg:PickPlaceR11EnvCfg"
        ),
        "robomimic_bc_cfg_entry_point": "isaaclab_tasks.manager_based.manipulation.pick_place.agents:robomimic/bc_rnn_low_dim.json",
    },
    disable_env_checker=True,
)

注册字段怎么理解

  • id：外部运行时使用的任务名，例如训练脚本里的 --task Isaac-PickPlace-R11-Abs-v0。
  • entry_point：要实例化的环境类。ManagerBased 任务通常是 isaaclab.envs:ManagerBasedRLEnv。
  • env_cfg_entry_point：指向你写的配置类，格式是 python.module:ClassName。
  • *_cfg_entry_point：可选，给训练、模仿学习或其他工具加载算法配置。
  • disable_env_checker：Isaac Lab 任务通常设为 True，避免 Gym 默认检查器误判复杂空间。
只写 env_cfg 但不注册时，脚本无法通过任务 ID 找到它。注册文件所在包也必须能被导入； 如果你新建了更深层目录，要确认上层 __init__.py 或任务发现机制会导入到这个注册模块。

6. 验证和调试

不建议一上来就训练。新机器人接入应该先做资产级验证，再做环境级验证，最后做任务级验证。

建议验证顺序

  1. USD 单独打开：确认 mesh、材质、关节层级、Articulation Root、碰撞体和质量惯量。
  2. robot cfg spawn：写最小脚本或复用 demo，只 spawn R11，按 play 看是否掉落、爆炸、姿态正确。
  3. 关节名匹配：确认 joint_names_expr 能匹配到预期 DOF，没有漏控或重复控制。
  4. 执行器参数：从小刚度/阻尼开始，逐步调到业务参数，观察抖动、穿透、跟踪误差。
  5. env_cfg 初始化：只跑 reset 和 zero/random agent，确认 observation/action 维度稳定。
  6. 任务逻辑：检查 success/failure 是否符合业务目标，reset 是否把物体和机器人放回合理范围。
  7. teleop/训练：最后接 XR、motion controller、RL 或 imitation learning。

常用命令

# 列出可注册环境，确认任务 ID 是否出现
./isaaclab.sh -p scripts/environments/list_envs.py

# 用随机动作跑环境，先看是否能创建和 step
./isaaclab.sh -p scripts/environments/random_agent.py --task Isaac-PickPlace-R11-Abs-v0 --num_envs 1

# 用零动作跑环境，更容易看初始姿态和稳定性
./isaaclab.sh -p scripts/environments/zero_agent.py --task Isaac-PickPlace-R11-Abs-v0 --num_envs 1

常见问题定位

现象 优先检查
机器人不可见或 mesh 丢失 USD 外部引用路径、meshes/ 是否完整、相对路径是否正确。
一按 play 就爆炸 碰撞体重叠、自碰撞、质量惯量异常、初始姿态穿地、solver iteration 太低。
机器人软或跟踪差 stiffness、damping、armature、effort_limit_sim 是否合理。
某些关节不动 joint_names_expr 是否匹配、USD drive 是否存在、关节是否 fixed/mimic、action 是否覆盖。
IK 方向不对 base link、end-effector link、URDF 坐标系、USD/URDF 是否一致、四元数顺序。
任务 ID 找不到 gym.register 是否执行、模块是否被导入、env_cfg_entry_point 路径是否写错。

7. 当前 R11 对照

结合当前仓库，R11 已经走到了“资产、robot cfg、env_cfg、注册任务”都存在的阶段。 下面是你现在可以重点阅读的文件和它们的作用。

文件 作用 建议阅读重点
assets/seres_r11/r11_0615.usd R11 主 USD。 Articulation Root、joint/link 名、碰撞体、自碰撞、mesh 引用。
assets/seres_r11/meshes/r11_0615/ R11 USD 依赖的 OBJ/MTL mesh 资源。 资源是否完整，是否有绝对路径依赖。
source/isaaclab_assets/isaaclab_assets/robots/seres_r11.py R11 机器人本体配置。 joint 分组、R11_A2_32DOF_REAL、R11_A2_HIGH_PD_CFG、执行器参数。
source/isaaclab_tasks/isaaclab_tasks/manager_based/manipulation/pick_place/pickplace_seres_r11_env_cfg.py R11 pick-place 任务配置。 ObjectTableSceneCfg、ActionsCfg、ObservationsCfg、TerminationsCfg、teleop pipeline。
source/isaaclab_tasks/isaaclab_tasks/manager_based/manipulation/pick_place/mdp/ 任务专属 observation、termination、event 函数。 成功条件、物体观测、末端位姿观测、reset 逻辑。
source/isaaclab_tasks/isaaclab_tasks/manager_based/manipulation/pick_place/__init__.py 注册 pick-place 任务 ID。 Isaac-PickPlace-R11-Abs-v0 和 Isaac-PickPlace-R11-MotionController-Abs-v0。
你下一步学习时，可以沿着这条链路读代码：先读 seres_r11.py 的 R11_A2_32DOF_REAL，再跳到 ObjectTableSceneCfg.robot 看它如何被 replace 到任务场景， 然后读 ActionsCfg 看外部 action 如何变成 R11 关节目标，最后读注册文件看任务 ID 如何暴露给脚本。

8. 新项目清单

如果以后你从 0 接一个新机器人或新任务，可以按这个 checklist 推进。

资产接收 checklist

  • 拿到主 USD，并确认能在 Isaac Sim/Kit 中打开。
  • 拿到所有 mesh、材质、贴图，且路径可在当前仓库中解析。
  • 拿到 URDF/MJCF 或至少 joint/link 命名表。
  • 拿到默认站姿、base link、末端 link、脚底 link、手爪 link。
  • 拿到关节限位、速度上限、力矩上限、质量惯量、PD 或电机参数。
  • 确认 floating base 还是 fixed base，是否需要自碰撞和 contact sensor。

robot cfg checklist

  • 定义资产路径常量，避免在多个 env_cfg 中重复写路径。
  • 定义 joint/link 分组，尤其是 action 会控制的关节和 observation 会读取的 link。
  • 定义 ArticulationCfg.spawn，包含 USD、刚体属性、articulation 属性。
  • 定义 init_state，保证机器人 reset 后不穿地、不自碰撞。
  • 定义 actuators，确保所有需要控制的 DOF 都被覆盖。
  • 为不同任务派生变体，例如固定底座、高 PD、禁用手部、只控制上半身。

env_cfg checklist

  • Scene: 机器人、任务物体、桌子/地面/灯光、相机/传感器。
  • Actions: action 维度、控制关节、缩放、IK frame、手爪映射。
  • Observations: policy 需要的状态，是否 concatenate，是否加噪声。
  • Rewards: RL 训练才需要；teleop/模仿学习可以暂时为空。
  • Terminations: 超时、失败、成功。
  • Events: reset、随机化、初始目标同步。
  • Env post init: decimation、sim.dt、episode_length_s、PhysX buffer。

注册和验证 checklist

  • 在任务目录 __init__.py 添加 gym.register。
  • 确认 env_cfg_entry_point 的模块路径和类名正确。
  • 运行 list_envs.py，确认任务 ID 能被发现。
  • 运行 zero_agent.py，确认 reset 和 step 不报错。
  • 运行 random_agent.py 或 teleop，确认 action 能控制预期关节。
  • 再开始训练、采集数据或接业务 pipeline。
