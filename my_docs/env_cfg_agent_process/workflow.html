AI Agent 生成 env_cfg：Workflow

把自然语言到 env_cfg 的过程拆成 Spec Builder、Generator 和 Validation Gate。

目录 总览 架构分层 Schema / Spec Workflow Orchestrator Skill 文件 落地路线

两阶段 Workflow

生成 env_cfg 不建议一步到位。更稳定的方式是两阶段：先补齐 spec，再用 spec 生成代码。

Stage A：Spec Builder 自然语言 → 结构化 spec → schema 校验 → 缺字段追问。
Stage B：Generator 已校验 spec → env_cfg / 注册 / 启动命令 → checklist 验收。

完整流程

1. 接收用户自然语言
2. Router 选择 skill：pick_place_vr
3. 加载 schema / prompt / checklist
4. Spec Builder loop
   4.1 AI 生成或更新 spec
   4.2 Orchestrator 用 schema 校验
   4.3 不通过：把错误转成追问，继续对话
   4.4 通过：冻结 spec，进入 Generator
5. Generator
   5.1 AI 根据 spec 生成 env_cfg 和注册改动
   5.2 输出 action layout、link/joint 清单、启动命令
6. Post Validation
   6.1 检查 import、文件路径、joint/link、action 维度、task 注册
   6.2 失败则回传错误给 AI 修复
7. 交付结果

Gate 的意义

Gate 是“不能跳过的检查点”。它把 AI 的自由生成限制在可控范围内。

Gate检查对象失败后怎么处理
Schema GateSpec 是否满足 schema。不进入代码生成，转成追问让用户补齐。
Asset Gaterobot cfg、USD/URDF、link/joint 是否存在。提示缺失文件或名称不匹配。
Action Gateteleop pipeline 输出维度是否等于 ActionsCfg 解析维度。阻断交付，要求修 action layout。
Registration GateGym task id 和 env_cfg entry point 是否注册成功。修注册文件或启动命令。
