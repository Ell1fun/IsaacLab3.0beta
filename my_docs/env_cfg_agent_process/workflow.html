两阶段 Workflow

生成 env_cfg 不建议一步到位。更稳定的方式是两阶段：先补齐 spec，再用 spec 进入模板生成器。 对仓库里已有完整模板的机器人，Stage B 不再让大模型写代码，而是由程序确定性生成。

Stage A：Spec Builder 本地解析或 AI：自然语言 → 粗 spec → preset enrichment → schema 校验 → 缺字段追问。
Stage B：Template Generator 已校验 spec → 模板化 env_cfg / 注册 / 启动命令 → checklist 验收。

完整流程

1. 接收用户自然语言
2. Router 选择 skill：pick_place_vr
3. 加载 schema / prompt / checklist
4. Spec Builder loop
   4.1 优先本地解析仓库内 preset 需求
   4.2 本地解析不够时，才调用 AI 生成或更新 spec
   4.3 Orchestrator 根据 robot/object presets 自动补齐仓库确定事实
   4.4 Placement Workflow 根据 robot.default_placement 自动计算 object.pose / target.pose
   4.5 Orchestrator 用 schema 校验
   4.6 不通过：把错误转成追问，继续对话
   4.7 通过：冻结 spec，进入 Template Generator
5. Template Generator
   5.1 根据 spec + presets 选择仓库已有 env_cfg 模板
   5.2 程序生成薄封装 env_cfg、task 注册和启动命令
6. Post Validation
   6.1 检查 import、文件路径、joint/link、action 维度、task 注册
   6.2 失败则阻断交付，优先修模板或 preset
7. 交付结果

Gate 的意义

Gate 是“不能跳过的检查点”。它把 AI 的自由生成限制在可控范围内。

Gate检查对象失败后怎么处理
Preset Enrichment根据 robot.preset / object.preset 自动补齐 EEF、关节、资产路径和自动命名。如果 preset 不存在或仍是 TODO，保留错误给 Schema/Asset Gate。
Schema GateSpec 是否满足 schema。不进入代码生成，转成追问让用户补齐。
Asset Gaterobot cfg、USD/URDF、link/joint 是否存在。提示缺失文件或名称不匹配。
Action Gateteleop pipeline 输出维度是否等于 ActionsCfg 解析维度。阻断交付，要求修 action layout。
Registration GateGym task id 和 env_cfg entry point 是否注册成功。修注册文件或启动命令。

最终命令输出

Generator 的交付结果里必须输出一条可直接复制运行的 teleop 命令。 命令中的 --task 必须使用本次注册出来的 task.gym_id。 

./isaaclab.sh -p scripts/environments/teleoperation/teleop_se3_agent.py \
  --task Isaac-Auto-PickPlace-UnitreeG1-SteeringWheel-Teleop-v0 \
  --visualizer kit \
  --xr \
  --cloudxr_env cloudxrjs
这里的 task id 只是示例。真实输出必须替换成本次 spec 里的 task.gym_id，也就是注册文件里新增的 Gym ID。
