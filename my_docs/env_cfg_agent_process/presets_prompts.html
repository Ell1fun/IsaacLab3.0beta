AI Agent 生成 env_cfg：Presets & Prompts 参考

把 presets/ 与 prompts/ 两类“可维护资产”说清楚：应包含哪些字段、各字段由谁消费、以及 prompt 的职责边界。

这页解决什么问题

维护 skill 最容易变乱的两块就是 presets 与 prompts。 这页把它们当成“配置资产”来管理：字段要稳定、边界要清晰、由程序消费的事实要可追溯。

快速定位：presets 的字段最终会被 presets.py 用于 enrichment（补齐 spec），模板匹配/适配则由 generator_workflow.py 消费。 prompts 的输出必须受 schema、workflow gate 约束，不能直接自由生成最终代码。

Presets：总原则

  • 只存“仓库确定事实”：例如 EEF link、joint 列表、已有模板 module/class、已知资产 USD 路径。
  • 不要让 TODO 混进最终生成：如果 usd_path 仍是 TODO，Stage B 必须阻断。
  • 字段分层：enrichment 用的字段、命名用的字段、模板选择用的字段、适配用的字段应分开看。
  • 允许继承：通过 inherits 复用共同事实，避免重复维护。

robot_presets.yml：字段清单

每个机器人 preset 是一个 YAML object，key 是 preset 名（例如 unitree_g1_inspire_ftp、fourier_gr1t2_high_pd）。

类别字段用途是否建议必填
标识 display_name、robot_slug 用于自动命名 task.gym_id / 文件 stem（见 presets.py.task_names_from_presets）。 建议必填
模板/引用 reference_env_cfg 目标机器人已有模板的参考 env_cfg（用于 structured snippets 抽取与适配上下文）。 建议必填
输出位置 output_dir、registration_module 生成文件写入位置与注册文件位置（目前 pick_place 固定在任务目录下）。 建议必填
模板映射 supported_teleop_templates 决定是否存在 exact template：按 control.teleop.input_source 索引到 module/class。 建议必填（至少 hand tracking）
机器人事实 robot_cfg_import、base_link_name、eef_link_names spec enrichment：避免模型猜 EEF/base，直接由 preset 填入。 建议必填
控制/IK controlled_joint_names Pink IK / action layout 的确定事实（程序或模板会依赖它）。 推荐填写
手部动作 hand_joint_names 手指关节顺序的确定事实。对 trigger-open/close 这类映射必须有完整列表。 有手就必填
初始姿态 init_state、idle_wrist_pose teleop 启动时的中性位姿；部分模板还会用于 rebase。 推荐填写
桌子/摆放 default_table、default_placement placement workflow：按桌子中心 + offset 计算 object/target pose。 推荐填写
Motion Controller 适配 motion_controller_adaptation 当缺 exact template 但要走 adaptation 时，提供 robot 专属 wrist offset 等事实，降低模型推断风险。 仅 motion controller 需要

supported_teleop_templates 的 entry

每个 input_source 对应一个 entry，最小字段如下：

supported_teleop_templates:
  openxr_hand_tracking:
    module: pickplace_unitree_g1_inspire_hand_env_cfg
    class: PickPlaceG1InspireFTPEnvCfg

如果希望 adaptation 使用不同参考（例如统一用 tri 版本），可选加：

supported_teleop_templates:
  openxr_controller:
    module: pickplace_seres_r11_tri_env_cfg
    class: PickPlaceR11TriEnvCfg
    adaptation_reference_env_cfg: source/.../pickplace_seres_r11_tri_env_cfg.py
    adaptation_reference_module: pickplace_seres_r11_tri_env_cfg
    adaptation_reference_class: PickPlaceR11TriEnvCfg

motion_controller_adaptation 的 entry

motion_controller_adaptation:
  reference_env_cfg: source/.../fixed_base_upper_body_ik_g1_env_cfg.py
  left_controller_offset_rpy_deg: [45.0, 180.0, -90.0]
  right_controller_offset_rpy_deg: [-135.0, 0.0, 90.0]
  use_wrist_rotation: false
  use_wrist_position: false
  grasp_scalar: max_trigger_squeeze
这里的 offset 是“controller grip frame → robot EEF task frame”的对齐补偿，强依赖机器人末端 link 坐标系定义； 因此不能直接从其他机器人迁移，必须来自本机器人参考或标定流程。

object_presets.yml：字段清单

物体 preset 的目标是固定“资产事实”，并为 placement workflow 提供必要信息。

字段用途是否建议必填
display_name、object_slug用于自动命名与文件 stem。建议必填
usd_pathspawn 物体资产路径；若为 TODO 必须阻断。建议必填
scale物体缩放。推荐
mass当使用 single rigid body wrapper 时用于质量属性。可选
single_rigid_body是否需要“单刚体包装”以满足 RigidObject/PhysX 约束。推荐
reference_env_cfg当 usd_path 需要从现有任务文件提取时的参考入口。可选
default_quat_xyzw、default_target_quat_xyzwplacement workflow 生成 pose 时的默认朝向。可选
tabletop_z默认桌面高度（当 robot.default_placement 未提供 z 或需覆盖时）。可选
物体 preset 里可能存在历史字段 pose/default_target_pose。当前主路径以 placement workflow 为准： 用户未给 pose 时，使用 robot.default_table.pose 与 robot.default_placement 计算 object/target。

Prompts：总原则

  • prompt 是“行为规范”：告诉模型怎么填 spec、怎么输出 JSON、什么时候必须阻断。
  • prompt 不是代码生成器本体：最终写文件必须经过 workflow gate（schema、tests、write gate）。
  • 按职责拆分：Spec Builder / Template Adaptation / Generator 三类 prompt 不要混用。

prompts/：文件职责一览

文件何时会用输入输出边界
pick_place_vr_spec_builder.md Stage A schema gate 失败且开启 --enable_api 时。 user_text + schema + draft_spec + validation_errors。 补齐后的 PickPlaceVRSpec（YAML/JSON）。 不写最终 env_cfg；不发明 joint/link/usd 路径。
pick_place_vr_template_adaptation.md Stage B 缺 exact template 且开启 --enable_api 时。 spec + 目标机器人模板 snippets + 同输入源参考 snippets + adaptation preset。 adaptation_spec（JSON）。 禁止输出 Python；最终 env_cfg 必须由程序确定性渲染。
pick_place_vr_generator.md 作为 fallback/参考：未来支持非模板场景或其他 skill 时使用。 已通过 schema gate 的 spec。 files/commands 的结构化对象。 当前 pick_place_vr 主路径优先 template generator，不依赖该 prompt。
env_cfg_generator.md 早期通用 prompt（保留作参考）。 不稳定。 不稳定。 不建议作为生产路径。

新增一个 robot/object preset 的最小步骤

  1. 在 presets/robot_presets.yml 或 presets/object_presets.yml 增加条目。
  2. 同步更新 schemas/pick_place_vr_spec.schema.yml 的 enum（让 robot.preset/object.preset 可选）。
  3. 补一个 examples 输入（可选但强烈建议），避免后续回归时忘掉预期。
  4. 如果新增的是 motion controller 支持：尽量提供本机器人 motion_controller_adaptation 的参考与 offsets；否则应明确 blocked。
