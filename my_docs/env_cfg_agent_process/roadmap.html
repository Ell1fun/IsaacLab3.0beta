AI Agent 生成 env_cfg：落地路线

从当前最小雏形到成熟产品化 skill 的推进计划。

目录 总览 架构分层 Schema / Spec Workflow Orchestrator Skill 文件 落地路线

当前状态

  • 已经有 PickPlaceVRSpec schema。
  • 已经有最小 orchestrator：route / template / validate / generate。
  • 已经明确第一阶段支持 IsaacLab 仓库内封装好的人形机器人预设。
  • 已经明确成熟形态需要 AI API、会话状态、schema gate、post validation gate。

下一步优先级

  1. 补 pick_place_vr_spec_builder.md：定义自然语言到 spec 的补齐规则。
  2. 补 pick_place_vr_generator.md：定义 spec 到 env_cfg 的生成规则。
  3. 补 post_generation_validation.md：定义生成后的检查清单。
  4. 补 R11/G1 examples：用真实任务反推 schema 是否够用。
  5. 把 orchestrator 的 API 分支从 raw 输出升级为：解析 spec → schema 校验 → 追问循环。
  6. 再实现 env_cfg 写文件、注册 task、运行静态检查。

产品化路线

阶段目标交付物
V0本地理解和验证流程。schema + 文档 + CLI orchestrator。
V1接入 AI API，能对话补齐 spec。spec_builder_loop + schema gate。
V2能从 spec 生成 env_cfg 并注册任务。generator + post validation。
V3接入 Chat UI / IDE 插件 / 服务端。常驻 orchestrator + 多用户会话状态。
V4支持用户自带 USD 的机器人接入。新的 asset-to-robot-cfg skill。

当前不做的事

  • 不从零生成机器人 URDF / robot cfg。
  • 不自动猜 joint/link/EEF。
  • 不把 API Key 写进 repo。
  • 不跳过 schema gate 直接生成代码。
