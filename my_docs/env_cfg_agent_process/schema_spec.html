Schema 和 Spec 的关系

spec 是 specification 的缩写，表示“规格/需求说明”。 在这里，PickPlaceVRSpec 是一个结构化任务需求说明书；schema 是约束这份说明书长什么样的规则。

概念作用例子
Schema定义字段、类型、枚举、必填/可选、条件必填。pick_place_vr_spec.schema.yml
Spec一次具体任务的结构化输入，必须满足 schema。robot.preset: unitree_g1_inspire_ftp
Gap Analysis对照 schema 找缺失字段，并转成追问。缺 eef_link_names 就问用户左右 EEF link。

Schema 负责约束什么

  • 允许哪些字段，例如 robot、scene、object、target、control。
  • 字段类型是什么，例如字符串、数字、布尔、数组、pose7。
  • 哪些字段是必填，例如 robot.preset、scene.table、control.mode。
  • 哪些值允许出现，例如 robot.preset 只能选当前支持的人形机器人预设。
  • 条件必填，例如启用 teleop 时必须补齐 world_T_anchor 和 idle wrist pose。

Spec Builder 的目标

Spec Builder 不负责写代码，它只负责把用户自然语言逐步补齐成一份能通过 schema 校验的 spec。

用户：帮我用 G1 做一个 VR pick_place
  ↓
AI 生成 spec 草稿
  ↓
Schema 校验发现缺 eef_link_names / table usd / object usd
  ↓
AI 追问用户
  ↓
用户补齐
  ↓
Spec 通过 gate，进入 Generator

用户 Prompt 应该长什么样

用户不需要自己写 YAML。理想体验是用户用自然语言描述任务，Spec Builder 根据 schema 和 prompt 规则生成 spec 草稿。 

我希望用宇树的机器人做一个抓取方向盘的遥操任务。

这句话会被解析成几个关键信息：

  • 宇树：优先匹配 unitree_g1_inspire_ftp，因为它是当前仓库里最接近 VR/hand tracking pick_place 的 Unitree 样例。
  • 方向盘：匹配 object.preset: steering_wheel。
  • 遥操：匹配 control.teleop.enabled: true，默认走 openxr_hand_tracking。
  • 抓取：匹配 manager_based/manipulation/pick_place。

当前支持的物体预设

对 pick_place 任务来说，抓取物体也需要约束成 enum。这样模型不会随便编一个不存在的 USD 路径。

object.preset来源说明
steering_wheelR11 / GR1T2 pick_place 样例方向盘，当前最适合“抓取方向盘遥操任务”的默认物体。
bottled_water_c01R11 tri 样例引用瓶装水，可用于简单抓取/搬运。
factory_m16_nut_greennut pour 任务资产绿色 M16 螺母，适合螺母/投放类任务。
exhaust_pipeGR1T2 exhaust pipe 任务排气管，需要参考 exhaustpipe 任务资产。
如果用户说的物体不在 enum 里，当前 skill 不应编造路径；应追问用户是否改用已有 preset，或进入后续“用户给 USD 生成资产”的独立 skill。

自动命名与注册区分

自动生成的 env_cfg 和注册任务必须和仓库已有手写任务明显区分，避免误覆盖、误复用。
