Schema 和 Spec 的关系

spec 是 specification 的缩写，表示“规格/需求说明”。 在这里，PickPlaceVRSpec 是一个结构化任务需求说明书；schema 是约束这份说明书长什么样的规则。

概念作用例子
Schema定义字段、类型、枚举、必填/可选、条件必填。pick_place_vr_spec.schema.yml
Spec一次具体任务的结构化输入，必须满足 schema。robot.preset: unitree_g1_inspire_ftp
Gap Analysis对照 schema 找缺失字段，并转成追问。缺 eef_link_names 就问用户左右 EEF link。

Schema 负责约束什么

  • 允许哪些字段，例如 robot、scene、object、target、control。
  • 字段类型是什么，例如字符串、数字、布尔、数组、pose7。
  • 哪些字段是必填，例如 robot.preset、scene.table、control.mode。
  • 哪些值允许出现，例如 robot.preset 只能选当前支持的人形机器人预设。
  • 条件必填，例如启用 teleop 时必须补齐 world_T_anchor 和 idle wrist pose。

Spec Builder 的目标

Spec Builder 不负责写代码，它只负责把用户自然语言逐步补齐成一份能通过 schema 校验的 spec。

用户：帮我用 G1 做一个 VR pick_place
  ↓
AI 生成 spec 草稿
  ↓
Schema 校验发现缺 eef_link_names / table usd / object usd
  ↓
AI 追问用户
  ↓
用户补齐
  ↓
Spec 通过 gate，进入 Generator
