这个文档库解决什么问题

这个目录用于沉淀“AI Agent 自动生成 Isaac Lab pick_place VR/teleop env_cfg”的工程方案。 它不是单纯写一个 prompt，而是把 skill 文件、workflow 流程、orchestrator 编排器、schema/spec 约束拆清楚。

Skill 可复用的规范资产：schema、prompt、checklist、模板和 examples。
Workflow 任务状态机：自然语言 → spec builder → preset enrichment → schema gate → template generator。
Orchestrator 执行控制层：选 skill、调用 AI API、维护对话状态、强制校验、决定是否进入下一步。
Spec 结构化需求说明书：把用户零散自然语言变成可验证、可追溯、可复用的输入。

推荐阅读顺序

  1. 架构分层：先搞清楚 skill / workflow / orchestrator / AI API 的边界。
  2. 开发演进：理解为什么从单文件 orchestrator 演进到 presets、template generator 和模块拆分。
  3. Schema / Spec：理解为什么先补齐 spec，schema 到底约束什么。
  4. Workflow：理解两阶段流程：Spec Builder 和 Generator。
  5. Orchestrator：理解成熟 skill 为什么能“自动选中并读取 schema”。
  6. 代码导读：逐函数理解 orchestrator.py 的职责和执行链路。
  7. 模块与流程图：用 flowchart 看清每个模块职责，以及什么时候调 AI、什么时候直接用 presets/template。
  8. Preset Enrichment：理解为什么要用机器人/物体 preset 自动补齐 spec。
  9. Template Generator：理解 env_cfg 薄封装、task 注册和启动命令如何由代码确定性生成。
  10. Placement Workflow：理解 object.init_state 和 target_pose 如何按机器人工作空间自动计算。
  11. Skill 文件：看当前 repo 里哪些文件是执行材料，哪些是学习文档。
  12. Presets & Prompts：把 presets/ 字段清单与 prompts/ 职责边界一次看清，后续维护不容易跑偏。
  13. 开发日志：跟踪工程化评审问题、修复优先级和对应代码变更。
  14. 落地路线：从当前最小雏形到产品化入口应该怎么推进。

当前第一阶段范围

  • 只做 IsaacLab 仓库里已经封装好的 humanoid / 类 humanoid 机器人预设。
  • 先聚焦 manager_based/manipulation/pick_place，不一开始泛化所有任务类型。
  • 先做可控的生成闭环：补齐 spec、校验、生成 env_cfg、注册任务、输出启动命令。
  • 暂不做“用户只给 USD，自动生成 URDF / robot cfg / retargeting 资产”的 skill；这属于后续独立能力。
当前可执行雏形在 ../env_cfg_skills/orchestrator.py；schema 在 ../env_cfg_skills/schemas/pick_place_vr_spec.schema.yml。
