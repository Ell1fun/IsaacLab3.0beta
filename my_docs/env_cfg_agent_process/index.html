AI Agent 生成 env_cfg：总览

从 skill、workflow、orchestrator、schema/spec 四层理解自动生成 env_cfg 的完整方案。

目录 总览 架构分层 Schema / Spec Workflow Orchestrator Skill 文件 落地路线

这个文档库解决什么问题

这个目录用于沉淀“AI Agent 自动生成 Isaac Lab pick_place VR/teleop env_cfg”的工程方案。 它不是单纯写一个 prompt，而是把 skill 文件、workflow 流程、orchestrator 编排器、schema/spec 约束拆清楚。

Skill 可复用的规范资产：schema、prompt、checklist、模板和 examples。
Workflow 任务状态机：自然语言 → spec builder → schema gate → generator → validation gate。
Orchestrator 执行控制层：选 skill、调用 AI API、维护对话状态、强制校验、决定是否进入下一步。
Spec 结构化需求说明书：把用户零散自然语言变成可验证、可追溯、可复用的输入。

推荐阅读顺序

  1. 架构分层：先搞清楚 skill / workflow / orchestrator / AI API 的边界。
  2. Schema / Spec：理解为什么先补齐 spec，schema 到底约束什么。
  3. Workflow：理解两阶段流程：Spec Builder 和 Generator。
  4. Orchestrator：理解成熟 skill 为什么能“自动选中并读取 schema”。
  5. Skill 文件：看当前 repo 里哪些文件是执行材料，哪些是学习文档。
  6. 落地路线：从当前最小雏形到产品化入口应该怎么推进。

当前第一阶段范围

  • 只做 IsaacLab 仓库里已经封装好的 humanoid / 类 humanoid 机器人预设。
  • 先聚焦 manager_based/manipulation/pick_place，不一开始泛化所有任务类型。
  • 先做可控的生成闭环：补齐 spec、校验、生成 env_cfg、注册任务、输出启动命令。
  • 暂不做“用户只给 USD，自动生成 URDF / robot cfg / retargeting 资产”的 skill；这属于后续独立能力。
当前可执行雏形在 ../env_cfg_skills/orchestrator.py；schema 在 ../env_cfg_skills/schemas/pick_place_vr_spec.schema.yml。
