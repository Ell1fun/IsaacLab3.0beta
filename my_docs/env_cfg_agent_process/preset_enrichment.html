为什么要加 presets

schema 只负责约束 spec 的结构，例如哪些字段必填、字段类型是什么、哪些 enum 合法。 但 schema 不知道 GR1T2 的 EEF link 名称、Pink IK 受控关节顺序、手部关节顺序、参考 env_cfg 路径和正确注册目录。 这些是仓库里的确定事实，不应该让模型每次自由猜。

所以新增 preset enrichment：模型只需要识别 robot.preset 和 object.preset，orchestrator 再用本地 preset 表把确定字段补齐。

它解决了模型的什么困境

模型原来的困境原因preset enrichment 后怎么解决
EEF link 写成 TODOschema 只要求有字段，不知道具体 link 名。robot_presets.yml 固化 left_hand_pitch_link/right_hand_pitch_link 等。
Pink IK joints 不敢写模型怕编造 joint 顺序。从参考 env_cfg 抽取后写入 controlled_joint_names。
hand_joint_names 缺失teleop action layout 对顺序很敏感。preset 固化和 pipeline 匹配的 hand joint 顺序。
table/object USD 变成 TODO用户自然语言不会提供资产路径。object_presets.yml 和 robot 默认 table 自动补齐。
生成路径少一层 isaaclab_tasks模型只凭路径模式猜。generator prompt/checklist 写死正确输出目录。

新增文件

文件作用
env_cfg_skills/presets/robot_presets.yml机器人 preset 映射表：robot cfg、base link、EEF、IK joints、hand joints、init state、默认 table、默认 placement、参考 env_cfg、输出目录。
env_cfg_skills/presets/object_presets.yml物体 preset 映射表：USD 路径、scale、质量、是否单刚体、默认朝向等物体自身事实。

GR1T2 + 水瓶例子

用户说：

帮我生成一个傅里叶GR1T2抓取水瓶的遥操任务

模型只要识别出：

robot:
  preset: fourier_gr1t2_high_pd
object:
  preset: bottled_water_c01

orchestrator 会自动补齐：

  • robot.eef_link_names.left/right：left_hand_pitch_link/right_hand_pitch_link
  • robot.base_link_name：base_link
  • robot.controlled_joint_names：GR1T2 双臂 Pink IK 受控关节顺序
  • robot.hand_joint_names：GR1T2 双手 22 个 action joint 顺序
  • scene.table.usd_path：PackingTable 路径
  • object.usd_path：瓶装水 SimReady 路径
  • task.gym_id：Isaac-Auto-PickPlace-FourierGR1T2-BottledWaterC01-Teleop-v0

边界

  • preset enrichment 只补仓库中已经确定的信息，不负责发明新资产。
  • 如果用户给的机器人或物体不在 preset 中，仍然需要追问或进入后续“用户给 USD 生成资产”的独立 skill。
  • 如果 preset 中仍是 TODO，例如某些资产路径未解析，generator 不应该硬生成最终代码。
