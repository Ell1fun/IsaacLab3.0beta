AI Agent 生成 env_cfg：Template Generator

解释 orchestrator 如何不用大模型，直接用代码确定性生成 env_cfg 薄封装、task 注册内容和 teleop 启动命令。

为什么不用模型写 env_cfg

对仓库里已有完整 pick_place teleop 模板的机器人，env_cfg 的控制器、teleop pipeline、IK、observations、terminations 已经在参考文件里写好了。 这类任务不应该让大模型重新写一整份代码，因为模型容易漏路径、猜 joint、写 TODO 或覆盖手写任务。

当前工程决策：模型最多负责把用户自然语言补成 spec；仓库内已有机器人使用 template generator 确定性生成文件。

输入和输出

阶段内容
输入已经通过 schema gate 的 spec，且经过 robot/object preset enrichment。
输出 1自动 env_cfg 薄封装文件，例如 auto_pickplace_fourier_gr1t2_bottled_water_c01_teleop_env_cfg.py。
输出 2pick_place/__init__.py 的注册后完整内容或 dry-run payload。
输出 3可复制运行的 teleop 启动命令。

第一步：选择已有模板

_template_base_for_robot(robot_preset) 根据 robot.preset 选择仓库已有的基础 env_cfg。 这些基础 env_cfg 已经包含复杂的 teleop pipeline、IK action、observation、termination 和事件逻辑。

robot.preset继承的基础模板
fourier_gr1t2_high_pdpickplace_gr1t2_env_cfg.PickPlaceGR1T2EnvCfg
unitree_g1_inspire_ftppickplace_unitree_g1_inspire_hand_env_cfg.PickPlaceG1InspireFTPEnvCfg
seres_r11_a2_high_pdpickplace_seres_r11_env_cfg.PickPlaceR11EnvCfg
如果 robot preset 没有基础模板，例如当前 unitree_h1，template generator 会阻断，而不是让模型硬写。

第二步：生成 env_cfg 薄封装

_render_template_env_cfg(spec) 不从零生成 env_cfg，而是生成一个继承已有模板的子类。 它只覆盖 spec 中确定的任务参数，例如物体 USD、物体 scale、物体初始 pose、桌子 pose、target pose。 

from .pickplace_gr1t2_env_cfg import PickPlaceGR1T2EnvCfg


class AutoPickPlaceFourierGR1T2BottledWaterC01TeleopEnvCfg(PickPlaceGR1T2EnvCfg):
    def __post_init__(self):
        super().__post_init__()

        self.scene.object.spawn.usd_path = f"{ISAAC_NUCLEUS_DIR}/SimReady/.../bottledWater...usd"
        self.scene.object.spawn.scale = (1.0, 1.0, 1.0)
        self.scene.object.init_state.pos = (-0.45, 0.45, 0.9996)
        self.scene.object.init_state.rot = (0.0, 0.0, 0.0, 1.0)

这样做的好处是：原模板里的 IK、teleop pipeline、action layout、observation、termination 都不会被模型破坏。

第三步：生成注册内容

_render_registered_init(spec, module_name, class_name) 会读取现有 source/isaaclab_tasks/isaaclab_tasks/manager_based/manipulation/pick_place/__init__.py。 如果 task.gym_id 没有注册过，就追加一个带 Auto 前缀的 gym.register(...) 块。 

gym.register(
    id="Isaac-Auto-PickPlace-FourierGR1T2-BottledWaterC01-Teleop-v0",
    entry_point="isaaclab.envs:ManagerBasedRLEnv",
    kwargs={
        "env_cfg_entry_point": f"{__name__}.auto_pickplace_fourier_gr1t2_bottled_water_c01_teleop_env_cfg:AutoPickPlaceFourierGR1T2BottledWaterC01TeleopEnvCfg",
        "robomimic_bc_cfg_entry_point": f"{agents.__name__}:robomimic/bc_rnn_low_dim.json",
    },
    disable_env_checker=True,
)
注册 ID 和文件名都带 Auto / auto_pickplace_，用于和仓库手写任务明显区分，避免覆盖原任务。

第四步：生成启动命令

_teleop_command_for_spec(spec) 不需要模型，直接读取 task.gym_id 拼命令。 

./isaaclab.sh -p scripts/environments/teleoperation/teleop_se3_agent.py \
  --task Isaac-Auto-PickPlace-FourierGR1T2-BottledWaterC01-Teleop-v0 \
  --visualizer kit \
  --xr \
  --cloudxr_env cloudxrjs

第五步：dry-run 和写文件

_run_template_generator_workflow(spec) 只负责返回 payload；真正是否写入由 _write_generated_files(generated, dry_run) 决定。

模式行为
dry_run: true只输出 DRY_RUN:/abs/path，不改仓库文件。
--write允许把生成的 env_cfg 和注册内容真正写入 repo。

完整例子：GR1T2 + 水瓶

python my_docs/env_cfg_skills/orchestrator.py generate "帮我生成一个傅里叶GR1T2抓取水瓶的遥操任务"

这条命令会走：

  1. 本地 spec parser：识别 fourier_gr1t2_high_pd 和 bottled_water_c01。
  2. preset enrichment：补齐 EEF、IK joints、hand joints、USD 路径、自动 task id。
  3. template generator：继承 PickPlaceGR1T2EnvCfg 生成薄封装。
  4. 注册生成器：追加 Isaac-Auto-PickPlace-FourierGR1T2-BottledWaterC01-Teleop-v0。
  5. 命令生成器：输出 teleop_se3_agent.py --task ...。
