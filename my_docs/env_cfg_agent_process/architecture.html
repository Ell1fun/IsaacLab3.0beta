四层架构

成熟的 agent skill 不是“一个 prompt 解决所有事”，而是分成四层。

层职责在本项目中的落点
用户入口接收自然语言需求，可以是 Chat UI、IDE 插件、API、CLI。当前用 CLI 演示；未来可以接服务端或 IDE。
Orchestrator路由选 skill、加载材料、调用 AI API、保存会话状态、强制 gate。env_cfg_skills/orchestrator.py
Workflow定义流程顺序和状态机：补齐 spec，再生成代码，再验收。写在 orchestrator 的执行逻辑和文档流程里。
Skill提供可复用材料：schema、prompt、checklist、示例和模板。env_cfg_skills/ 目录。

三者边界：Skill / Workflow / Orchestrator

Skill 是材料 告诉系统“允许什么、怎么生成、怎么验收”。它不负责自己运行。
Workflow 是流程 告诉系统“先做什么、后做什么、什么时候允许进入下一步”。
Orchestrator 是执行器 真正调用 AI API、读取文件、校验 schema、追问用户、写文件。
AI API 是生成器 负责理解自然语言和生成文本/代码，但不应该负责流程 gate。

成熟 skill 为什么看起来能“自动触发”

用户看到的是“我说一句话，AI 自动用了某个 skill”。实际背后通常是：平台先用 router 选中 skill，再把该 skill 的 schema/prompt 注入模型调用，并在程序侧做校验。 

用户自然语言
  ↓
Router 选择 skill
  ↓
加载 skill assets（schema / prompt / checklist）
  ↓
调用 AI API
  ↓
Schema / checklist gate
  ↓
返回结果或继续追问
模型本身不会凭空读取你的 repo 文件。必须由 orchestrator 或平台把 skill 注册并加载给模型。
