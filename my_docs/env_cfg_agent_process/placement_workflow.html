为什么不能直接用 object preset 里的固定坐标

之前 bottled_water_c01 的 preset 里直接写了 [-0.45, 0.45, 0.9996]。 这个坐标对某些模板可能能看见物体，但它没有考虑机器人本体、桌子中心、手臂可达范围和目标放置点。 因此同一个水瓶换到 Unitree G1 时，就可能离机器人过远。

新规则：物体 preset 描述物体自身事实；机器人 preset 描述工作空间；placement preset 描述语义摆放点；workflow 负责计算最终 object.pose、target.pose 和 scene_objects[].pose。

职责拆分

层级负责什么
Object presetUSD 路径、scale、质量、是否需要单刚体 spawner、默认朝向等物体自身事实。
Robot preset桌子位置、机器人工作空间、推荐主 object/target 相对桌面中心的默认偏移。
Placement preset维护 near_left_hand、near_right_hand、table_back 等语义位置相对桌面中心的偏移。
Placement workflow如果用户没有明确给坐标，就根据 table_center + offset 计算主 object、target 和 scene objects 的 pose。
Agent / LLM只负责理解“靠近右手、放中间、放远一点”等意图，不直接猜最终绝对坐标。

阶段 A/B：多物体边界

当前扩展只支持 单主操作物体 + 多个附加场景物体。 主 object 仍然是唯一参与 pick-place success、termination 和 target 的物体； scene_objects 只负责摆放 props/distractors/obstacles。 

object:
  preset: steering_wheel
  placement:
    semantic: near_right_hand

scene_objects:
  - name: bottled_water
    preset: bottled_water_c01
    role: distractor
    placement:
      semantic: table_back
如果用户要求“水管和方向盘都要抓取并判定成功”，这属于阶段 C 多主物体任务，需要新的 success/termination/reward 设计；阶段 A/B 不会静默改现有 pick_place 成功条件。

当前实现

robot_presets.yml 里新增了 default_placement。 例如 Unitree G1 的桌子中心是 [0.0, 0.55, 0.0]，默认物体偏移是 [0.0, -0.10]。 因此 workflow 会把物体放到 [0.0, 0.45, 0.9996]，而不是旧的 [-0.45, 0.45, 0.9996]。 

default_table:
  pose:
    pos: [0.0, 0.55, 0.0]

default_placement:
  object_xy_from_table_center: [0.0, -0.10]
  target_xy_from_table_center: [0.25, -0.10]
  z: 0.9996

新增的 placement_presets.yml 负责语义摆放点，例如： 

default:
  named_placements:
    near_left_hand:
      xy_from_table_center: [0.0, 0.12]
      z_mode: tabletop
    near_right_hand:
      xy_from_table_center: [0.0, -0.12]
      z_mode: tabletop
    table_back:
      xy_from_table_center: [-0.30, 0.0]
      z_mode: tabletop

代码流程

_enrich_pick_place_vr_spec(spec)
  ↓
读取 robot preset、object preset 和 placement preset
  ↓
补齐 robot/table/object/scene_objects 的确定事实
  ↓
compute_default_pick_place_placement(...)
  - 如果用户已经明确给 object.pose：尊重用户
  - 如果用户没有给 object.pose：用 table_center + object offset 计算
  - 如果用户没有给 target.pose：用 table_center + target offset 计算
  ↓
semantic_pose_from_placement(...)
  - object.placement.semantic → object.pose
  - scene_objects[].placement.semantic → scene_objects[].pose
  ↓
schema gate
  ↓
template generator 写入 env_cfg

优先级

  1. 用户明确指定坐标：workflow 不覆盖。
  2. 用户没有指定坐标但给了 placement.semantic：使用 placement_presets.yml 计算。
  3. 用户没有指定坐标和 semantic：主 object/target 使用 robot.default_placement 自动计算。
  4. 没有 placement 规则：阻断或追问，不让模型硬猜。
