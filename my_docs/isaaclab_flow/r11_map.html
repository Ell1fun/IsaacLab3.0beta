R11 的控制方式概览（你现在看到的是不是“基本都是隐式 PD”？）

是的：在 seres_r11.py 这一层，R11 的关节驱动基本都通过 ImplicitActuatorCfg 配置， 所以从“关节如何产生力矩/力”的角度看，它主要是 drive/隐式 PD 体系。

但要注意：任务里你不一定直接给关节角。以 R11 pick-place 为例，ActionsCfg 用的是 Pink IK（任务空间控制）： 也就是说上层 action 可能是“末端位姿目标”，先经 IK 转成“关节目标”，底层再由隐式 drive（PD）在求解器里产生力矩并推进仿真。 

任务 action（末端位姿） → IK（求关节目标） → 隐式 drive/PD（求力矩） → 物理引擎更新状态
所以你看到的“IK 控制”并不和“隐式 PD”冲突：IK 和 PD 常常是上下两层，IK 决定关节目标，PD 决定怎么用力去追目标。

KGU / SETZ 是什么？08/11/14、70/90 又代表什么？

在 seres_r11.py 里，KGU 与 SETZ 是对两类不同“电机+减速器/关节模组”的命名标签，用来把一整套参数（armature、Kp/Kd、限幅、摩擦） 作为“型号档位”复用到不同关节上。它们不是 Isaac Lab 的通用术语，而是这份 R11 配置里沿用的硬件分类命名。

  • KGU：文件注释里写的是“谐波减速器（KGU 系列）”。
  • SETZ：文件注释里写的是“行星减速器（SETZ 系列）”。

后面的数字（例如 KGU_08/11/14、SETZ70/90）代表同系列里的不同规格档位。你不需要知道它精确对应“外径/型号编码”的行业含义， 只要把它当作“不同力矩/速度/等效惯量等级”的编号即可：数字越大，通常能力越强（文件里也能看到对应的力矩上限/armature 更大）。

标签 在 R11 里代表的含义（你需要掌握的） 你能在文件里看到的直接证据
KGU_08 较小等级的谐波关节模组（多用于小负载关节） EFFORT_LIMIT_KGU08 = 18.56、ARMATURE_KGU_08 = 0.12
KGU_11 中等级的谐波关节模组 EFFORT_LIMIT_KGU11 = 30.91、ARMATURE_KGU_11 = 0.32
KGU_14 较大等级的谐波关节模组（多用于肩/腰等较大关节） EFFORT_LIMIT_KGU14 = 45.74、ARMATURE_KGU_14 = 0.19
SETZ70 较小等级的行星关节模组（多用于脚踝/腰 yaw 这类） EFFORT_LIMIT_SETZ70 = 85、ARMATURE_SETZ70 = 0.013312
SETZ90 较大等级的行星关节模组（多用于腿部大关节） EFFORT_LIMIT_SETZ90 = 150、ARMATURE_SETZ90 = 0.04851
你在代码里判断“它们代表什么”的最可靠方式不是猜行业编码，而是看这份配置给它们绑定了什么：armature、effort/velocity limit、 stiffness/damping、friction。这些就是仿真里真正生效的含义。

具体到 R11 的 actuator 分配，你可以直接从 actuators 里读出“哪个部位用哪个档位”，例如：腿部 hip/knee 用 SETZ90， 脚踝用 SETZ70（并整体乘 2.0），手臂 shoulder/elbow/wrist 分别用 KGU14/11/08。

推荐阅读路径（从 robot cfg 到 env_cfg）

  1. 先读 seres_r11.py：看 robot 怎么 spawn、actuator 怎么分组、默认站姿。
  2. 再读 pickplace_seres_r11_env_cfg.py 的 SceneCfg：看它如何把 robot cfg replace 到场景里。
  3. 再读 ActionsCfg：看 action 是怎么从 teleop/IK 变成关节目标。
  4. 最后读 mdp 目录：看观测和成功/失败条件怎么定义。
你最近问到的“为什么分 legs/feet/hands、正则怎么匹配”，建议配合阅读 actuator / regex 扫盲。
