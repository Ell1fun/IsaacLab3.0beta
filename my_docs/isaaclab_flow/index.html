Isaac Lab 机器人任务接入流程

面向你当前的 R11 项目，把“业务方给资产 → 写机器人 cfg → 写 env_cfg → 注册任务 → 验证运行”的全流程拆成多页。 从这里开始阅读。

目录 总览 assets 清单 robot cfg env_cfg teleop pipeline actuator / regex 扫盲 坐标系/关节轴 任务注册 验证与调试 R11 对照

一图理解：代码结构怎么串起来

Step 1：assets 放 USD + meshes + 贴图 + URDF/MJCF + 参数表，让资产能被稳定解析。
Step 2：robot cfg（ArticulationCfg） 回答“机器人怎么 spawn、初始姿态、关节分组、actuator 参数”。
Step 3：env_cfg（任务） 回答“场景里有什么、动作/观测是什么、成功失败怎么判、怎么 reset”。
Step 4：注册 + 运行 把 env_cfg 挂到一个 Gymnasium ID 上，脚本就能创建环境。
关键分工：robots/*.py 专注“机器人本体”；*env_cfg.py 专注“任务/场景/MDP”。

推荐阅读顺序（从零到能改代码）

  1. assets 清单：先把“甲方交付 vs 工程侧补齐”的边界搞清楚。
  2. robot cfg：理解机器人本体怎么 spawn、actuator 怎么配。
  3. actuator / regex 扫盲：补齐 joint 分组、隐式 PD、参数模板等概念。
  4. 坐标系/关节轴：补齐 URDF axis/origin、pose(7)、SE(3)、EEF frame 这些概念。
  5. env_cfg：回到任务文件，理解 action/obs/reset/IK/nullspace 等如何落地。
  6. teleop pipeline：理解 OpenXR 输入如何被拼成 env action，并对比不同机器人为何写法不同。
  7. 任务注册：把 cfg 注册成可运行任务。
  8. 验证与调试：快速定位 “坐标不对/手感怪/关节顺序错” 这类问题。

你刚问到的扫盲点：看哪些页

  • 正则怎么读、expr 是什么、joint_names_expr 匹配到哪些关节：看 actuator / regex 扫盲。
  • 为什么 legs/feet/hands 要分组、什么叫“同一套参数模板”：也在 actuator / regex 扫盲，里面用 R11 的实际参数举例。
  • Link/Joint/World 的坐标系关系、URDF 的 origin/axis、roll/pitch/yaw 为什么会混：看 坐标系/关节轴。
  • 任务层（PickPlaceR11）怎么用 robot cfg：看 env_cfg 和 R11 对照。
  • 手追踪/手柄输入如何变成 action、R11 与 G1 pipeline 为什么不同：看 teleop pipeline。
