robot cfg 的目的和内容

robot cfg 解决“机器人本体怎么被加载和驱动”。它不关心具体任务（pick/place/locomotion/teleop），任务逻辑在 env_cfg 里写。

目录 总览 assets 清单 robot cfg env_cfg teleop pipeline actuator / regex 扫盲 坐标系/关节轴 任务注册 验证与调试 R11 对照

robot cfg 在代码里长什么样？

通常就是一个或多个 ArticulationCfg（有时会有不同变体）。

MY_ROBOT_CFG = ArticulationCfg(
  spawn=sim_utils.UsdFileCfg(...),
  init_state=ArticulationCfg.InitialStateCfg(...),
  actuators={ ... },
)
actuators 是 robot cfg 的核心之一：它把“关节分组 + PD/限幅/armature”等控制参数定义清楚。细节见 actuator / regex 扫盲。

robot cfg 一般写哪些内容

模块 写什么 为什么
路径常量 资产目录、USD 路径（必要时 URDF/mesh 路径） 避免在多个 env_cfg 重复写路径、减少路径解析错误
命名分组 腿/脚/腰/臂/头/手的 joint/link 名（可用 regex） 后续按分组配置 actuator、观测、接触、IK frame 等
spawn 配置 从 USD spawn、刚体属性、articulation 属性、自碰撞、contact sensor 决定仿真稳定性、碰撞、接触数据来源
init_state 根位姿、默认关节角、默认关节速度 reset 后姿态是否合理，是否穿地/自碰撞
actuators 关节组、PD、armature、摩擦、速度/力矩限制 决定“怎么驱动”而不是“任务做什么”
变体 cfg copy/replace 出 fixed base、高 PD、禁用手等变体 同一个机器人在不同任务/控制方式下需要不同参数

robot cfg 不应该放什么

  • 任务成功/失败条件、reward 计算。
  • policy observation 的具体拼接方式。
  • 桌子、物体、目标点、随机化策略等场景/任务元素（除非它属于机器人本体）。
