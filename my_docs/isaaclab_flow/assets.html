assets 目录应该有什么

目标是让 USD 在任何机器/任何工作目录下都能解析依赖，并且能支撑后续写 robot cfg、写 IK、写任务和调参。

目录 总览 assets 清单 robot cfg env_cfg teleop pipeline actuator / regex 扫盲 坐标系/关节轴 任务注册 验证与调试 R11 对照

建议交付内容

类别 建议内容 为什么需要
主资产 robot.usd/robot.usda/robot.usdc robot cfg 的 UsdFileCfg.usd_path 指向它，用来 spawn 机器人。
几何资源 meshes/ 下的 .obj/.stl/.dae/.fbx 等 USD 常外部引用 mesh；缺失会导致不可见或加载失败。
材质贴图 materials/、textures/、.mtl、.png/.jpg 可视化检查装配、朝向、link 区分；也能减少你排查坐标系的成本。
源模型 .urdf/.mjcf 或转换脚本说明 排查 joint axis、mimic、限位，做 IK/retargeting 时尤其有用。
物理参数表 力矩/速度上限、质量惯量、摩擦、PD 推荐值、电机/减速器信息 用于写 actuator 参数（见 actuator 扫盲）。
命名说明 joint/link 命名表、base link、脚底 link、末端 link、手指映射 env_cfg 会用名字来选关节/连杆做 action、observation、termination、contact 等。

常见坑：USD 引用绝对路径、Windows 路径、Nucleus 路径；换机器后加载失败。 资产交付时最好保证全部依赖都能被相对路径解析。

哪些文件通常是“工程侧补的”（不一定来自甲方交付）

以 R11 为例：除了 USD/mesh/贴图这种“资产本体”，为了让 teleop/任务能跑起来，项目里会新增一些“工程侧配置文件”，它们往往不是甲方直接交付的。

文件/类型 通常由谁准备 为什么需要
手部 URDF（例如 revo2_left_hand.urdf） 多为工程侧（也可能来自厂商 SDK/内部模型） 用于手指重定向/IK/碰撞语义等，和主机器人 USD 不一定是同一条资产链
DexPilot 配置（例如 revo2_left_hand_dexpilot.yml） 工程侧（IsaacLab/任务作者） 这是“手追踪 → 机器人手指关节”的映射策略配置，必须与手部 URDF、关节命名、触点 link 一致
你问到的 revo2_left_hand_dexpilot.yml 文件头部带 Isaac Lab 的版权声明，这通常意味着它是项目侧准备/集成进来的，而不是甲方资产包原封不动给的。
